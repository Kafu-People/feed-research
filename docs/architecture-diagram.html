TechTrend architecture

A personalised news pipeline. Workers turn thousands of feeds into deduplicated, judged stories; the API ranks them per topic for the web and mobile apps; Slack gets hourly reports, digests and Gemini research briefs.

1 · What runs where

Four long-running processes (the systemd units in backend/deploy/systemd). Postgres is the store, the job queue, the scheduler and the vector index. There's no message broker and no cron.

Clients API Slack Data stores Workers External services

2 · The pipeline, article to reader

Each stage is a job type in the Postgres queue. A stage finishing enqueues the next one in the same transaction, so a row can't be committed without its follow-up job.

Note: judge is registered as a stage but techtrend-worker.service has never listed it, and the repo doesn't say why. Also, brief fires once the local clock passes TT_BRIEF_HOUR (18:00), and discuss is off unless TT_BRIEF_DISCUSS_ENABLED=true.

3 · The three data layers

Information flows down only. import-linter fails the build if a lower layer's code imports upward, and no user action can change a shared value.

Shared

Holds
articles, stories, summaries, novelty, story type, source authority
Written by
collect · read · group · judge (workers). One row per real-world thing.
↓ read only

Topic

Holds
keyword lists, topic embeddings, match scores (kept 30 days)
Written by
match (workers), distiller on topic creation. Shared by users with the same list.
↓ read only

Personal

Holds
weights, seen list, events
Written by
API + feedback worker. One user; writes nothing outside itself.
